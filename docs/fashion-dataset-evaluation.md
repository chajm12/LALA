# LALA 패션 데이터셋 도입 평가

확인일: 2026-09-28. 사용자 제공 10개 링크(개별 Kaggle 데이터셋 8개, Kaggle 검색 페이지 1개, DeepFashion 1개)를 모두 조회했다. Kaggle 웹 페이지에서 설명이 비어 보이는 경우 공식 공개 메타데이터 API의 설명·라이선스·파일 목록을 확인했다. 데이터셋 이미지/CSV/JSON 본문 다운로드, 모델 학습, 데이터셋 서비스 연결은 수행하지 않았다. 아래 규모는 게시자가 제시한 수치이며 직접 전수 검사한 장수와 구분한다.

## 판단

**도움은 될 수 있지만, 폴더에 이미지를 추가하는 것만으로 현재 GPT/NVIDIA API 모델이 학습되지는 않는다.** 현재 앱은 외부 모델을 호출해 착장 명세·이미지·상품 후보를 만드는 구조다. 로컬 데이터 추가, 참조 이미지 검색, 성능 평가, 모델 가중치를 바꾸는 학습은 각각 다른 작업이다. 이 보고서를 작성한 코딩 에이전트 자체가 데이터셋으로 영구 학습된 것도 아니다.

이번 오류에는 데이터 부족보다 먼저 해결해야 할 정보 연결 문제가 있다. 예를 들어 `카고 팬츠`, `니트`, `와이드 팬츠`만 검색하면 카모 팬츠·민소매 니트·트랙 팬츠도 범주상 후보가 된다. 품목별 색상·소매·무늬·바지 종류가 이미지 생성과 검색 사이에 공통으로 유지되어야 한다. '하나만 변경'은 학습 이미지가 아니라 수정 범위 제어 문제다. 이 진단은 사용자 사례와 앱의 API 호출 구조에 근거한 엔지니어링 판단이다.

따라서 도입 순서는 다음이 적절하다.

1. **공통 품목 명세와 실제 상품의 대조를 먼저 고친다.** 이미지에 사용한 색상·소매·무늬·형태를 상품 검색에도 전달하고, 충돌하는 상품을 걸러낸다. 상품 페이지에서 다른 색상 옵션이나 추천 상품의 속성이 섞이지 않도록 한다.
2. **현재 앱에서 실패한 사례를 정답이 있는 평가셋으로 만든다.** '니트가 맞다' 대신 '버건디 무지 긴팔 크루넥 니트가 맞다'를 평가한다. 실제 상품의 색상 옵션까지 묶어야 한다.
3. **공개 데이터로 품목 분리·속성 인식·이미지 검색을 보강한다.** Fashionpedia는 속성/분할에, DeepFashion의 consumer-to-shop 또는 DeepFashion2는 착장 사진과 상품 사진을 연결하는 실험에 적합하다.
4. 평가에서 부족함이 남으면 학습 가능한 별도 시각 인코더/재순위화 모델을 학습한다. 현재 쓰는 호스팅 모델의 이름만 유지한 채 데이터 파일을 놓는 것으로는 이 과정이 일어나지 않는다. 특정 API 모델의 미세조정 지원 여부는 별도로 확인해야 한다.

**가장 실용적인 첫 데이터는 허가받은 현재 판매 상품 사진·옵션 정보와 LALA 룩북을 연결한 작은 자체 평가셋이다.** 공개 데이터는 오래된 해외 상품·다른 촬영 구도·다른 판매처 분포가 많아, 오늘 무신사에서 살 수 있는 특정 색상 상품을 대신 알려주지는 않는다. 개선 폭은 도입 전후 평가로 확인해야 하며, 이번 조사만으로 정확도가 몇 % 오른다고 말할 수 없다.

### 중복과 잘못 읽기 쉬운 통계

**Fashion Style과 Images and Text를 서로 독립적인 데이터셋으로 계산하지 않는다.** 공식 API에서 둘의 `totalBytes`는 4,196,832,264로 같고, 조회한 첫 10개 파일의 이름·바이트 크기도 모두 같았다. 예를 들어 `data.csv`는 27,152,694바이트, `data/10000.jpg`는 41,351바이트다. 이는 중복 가능성이 높다는 증거다. 파일 전체 해시를 비교하지 않았으므로 재포장 여부를 확정한 것은 아니다. 출처를 명시한 Images and Text를 우선 검토하고, 둘을 train/test로 분리해 성능을 과대평가하지 않도록 해야 한다. [Fashion Style](https://www.kaggle.com/datasets/zara2099/fashion-style-image-dataset), [Images and Text](https://www.kaggle.com/datasets/nirmalsankalana/fashion-product-text-images-dataset)

**Shop the Look의 동일성과 궁합을 구분한다.** 원논문은 Pinterest 주석에 정확한 상품 외에도 비슷한 스타일로 장면과 어울리는 상품이 포함된다고 설명한다. 이 원본 STL 자료를 잘라내어 '보이지 않는 어울리는 상품'을 추천하는 CTL 평가도 만든다. 따라서 궁합 평가에서 맞았다고 카모/무지나 색상 일치까지 검증된 것은 아니다. 또한 Kaggle 설명의 93,274쌍은 원논문 Table 1에서 Home 데이터 수치이며, 전처리 후 Pinterest Fashion은 47,739개 장면·38,111개 상품·72,198쌍이다. 가공 단계가 다를 수 있으므로 도입 시 원본 파일을 세어야 한다. [원논문, §3 및 Table 1](https://arxiv.org/pdf/1812.01748.pdf)

## 더 적절한 보완 데이터

### Fashionpedia — 속성과 의류 영역 구분

48,825장의 패션 이미지, 의류 주분류 27개·부위 19개·세부 속성 294개를 제공한다. 의류 영역별 마스크와 속성이 연결되어 있어 `긴팔 니트 ↔ 민소매 니트`, `무지 ↔ 패턴`, `겉옷 ↔ 이너` 문제를 진단하고 시각 검증기를 평가하는 데 적합하다. 이는 태스크 구성을 근거로 한 적합성 판단이며 LALA에서 성능 향상을 측정한 결과는 아니다. [공식 프로젝트](https://fashionpedia.github.io/home/), [원논문](https://arxiv.org/abs/2004.12276)

Fashionpedia만으로 정확한 판매처 SKU·브랜드·판매 색상 옵션을 알 수는 없다. LALA가 쓰는 `버건디/차콜/올리브/카멜` 색 체계와 현재 상품의 색상 라벨은 별도로 정규화해야 한다. 원단의 실제 성분·기능성 역시 사진으로 추정한 질감과 판매처의 성분 표기를 구분해야 한다.

주석·온톨로지는 CC BY 4.0이지만 이미지 저작권은 원 제공자에게 있으며 Flickr·Unsplash 등 원출처 이용 조건을 따라야 한다. 모든 이미지에 단일 CC BY 라이선스가 적용된다고 보면 안 된다. [공식 이용 조건](https://fashionpedia.github.io/home/data_license.html)

### DeepFashion consumer-to-shop / DeepFashion2 — 착장과 상품 사진의 대응

DeepFashion consumer-to-shop은 의류 33,881개, 사진 239,557장, 서로 다른 촬영 영역 간 대응 195,540쌍을 제시한다. 전신 착장 사진 속 옷을 상품 사진에서 찾는 평가에 가까워, 현재 목적에 가장 직접적인 첨부 자료다. 앞서 설명한 비상업 연구 제한을 따른다. [공식 벤치마크](https://mmlab.ie.cuhk.edu.hk/projects/DeepFashion/Consumer2ShopRetrieval.html)

DeepFashion2 공식 저장소의 전체 통계는 491,895장, 800,732개 의류 인스턴스, 873,234개 상점-소비자 대응쌍이다. 경계 상자·분할 마스크·가림·시점·랜드마크 등을 제공한다. 같은 `pair_id`라도 색/프린팅이 다른 `style`은 구분해야 하며, 유효한 동일 대응쌍은 같은 양수 `style`까지 맞춰야 한다. **13개 분류에 신발이 없으므로 뉴발란스·컨버스 오류까지 이것 하나로 해결할 수 없다.** 신발은 실제 상품 카탈로그와 별도 신발 평가 데이터가 필요하다. [공식 저장소의 주석 정의](https://github.com/switchablenorms/DeepFashion2)

전체 논문 규모와 실제 공개·승인받아 확보한 분할의 규모는 구분한다. 공식 다운로드는 신청 양식으로 비밀번호를 받도록 안내한다. 이번 조사에서는 해당 양식 본문 접근이 차단되어 DeepFashion2의 상업 이용 허용 여부를 확인하지 못했다. DeepFashion 1의 약관을 근거 없이 그대로 적용하거나, 오픈 저장소라는 이유로 상용 이용이 가능하다고 단정하지 않는다.

### 상품 카탈로그 원본 또는 정리된 고해상도 상품 데이터

학습 인프라를 바로 추가하지 않고 이미지+텍스트 검색을 시험하려면 [Param Aggraval 원본 고해상도 데이터](https://www.kaggle.com/datasets/paramaggarwal/fashion-product-images-dataset) 또는 그 출처가 명시된 [Images and Text 전처리본](https://www.kaggle.com/datasets/nirmalsankalana/fashion-product-text-images-dataset)이 실용적이다. 같은 원본의 여러 재배포판을 섞지 않고 하나를 고른다. 현재 한국 판매처의 재고·URL·옵션 색상은 포함된다고 가정하지 말고 실제 상품 조회로 갱신해야 한다.

## LALA에 적용할 데이터 설계

공개 데이터의 총량보다 다음과 같이 오류를 설명할 수 있는 정답을 만드는 것이 먼저다. 아래 수량은 권장 시작 규모이며 연구 결과로 보장된 최소 샘플 수는 아니다.

- **첫 평가셋:** 200~500개 품목 사례. 남성/유니섹스 상의·하의·신발·아우터를 포함하고, 사진에서 성별을 추정해 라벨링하지 않는다. 판매처가 제공한 상품 대상 분류를 사용한다.
- **한 사례의 내용:** 룩북 이미지와 해당 품목 영역, 요청 명세, 상품/색상 옵션 ID, 실제 대표 사진, 상품명·판매처 속성·URL·조회일, 일치/불일치 및 구체적인 이유.
- **품목 속성:** 상의/하의/신발/아우터, 세부 종류, 주색, 무지/카모/체크/프린트, 소매 길이, 바지 소재 표기와 실루엣, 여밈, 브랜드/모델, 신발 색상·하이/로우. 보이지 않거나 판매처에서 확인되지 않으면 unknown으로 둔다.
- **어려운 오답:** 같은 카고 팬츠지만 카모 패턴, 같은 뉴발란스 모델이지만 흰색, 같은 니트지만 민소매·프린트, 같은 와이드지만 트랙 팬츠, 같은 차콜이지만 반팔 하프집업, 같은 트렌치지만 카멜색인 후보를 함께 넣는다.
- **수정 요청 평가:** '상의와 아우터 둘 중 하나만'의 기대 변경 개수는 1개다. 수정 전후 모든 슬롯을 비교하며 변경 금지 슬롯의 명세가 유지되는지 검사한다. 이는 시각 데이터셋과 별도인 동작 평가다.
- **분할:** 같은 상품 ID·색상 옵션·중복 사진·같은 원본의 재포장 자료가 학습/평가 양쪽에 들어가지 않도록 상품 단위로 분리한다. 새로운 판매 시점/브랜드의 별도 평가도 둔다.

평가지표는 품목별 Top-1 적합률, 중요한 속성의 오답 통과율, 4개 슬롯 상품 확보율, 검색 지연 시간, 수정하지 않은 슬롯 유지율을 함께 본다. 많이 추천하는 대신 틀린 상품이 늘어나거나, 정확해 보이도록 결과를 모두 비우는 개선은 둘 다 피해야 한다. `확인 완료 / 가까운 대안 / 미확인`을 분리하고, 가까운 대안이면 바뀐 속성을 사용자에게 구체적으로 알려야 한다.

제품을 먼저 확정하고 해당 상품 사진을 참조하여 룩북을 생성하는 흐름도 중장기 실험 가치가 있다. 지금처럼 이미지를 먼저 만든 후 구매 가능한 대안을 찾는 경우보다 대상이 명확해진다. 다만 참조 이미지 기반 생성도 상품 디테일을 항상 보존하지는 않으므로 최종 이미지 검사는 계속 필요하다. 이 항목은 후속 설계 제안이며 이번 데이터 조사에서 구현하거나 성능 검증한 기능은 아니다.

## 조사 범위와 재현 방법

Kaggle 개별 페이지 외에 공식 공개 API의 `datasets/view/{owner}/{slug}`로 설명·라이선스를, `datasets/list/{owner}/{slug}?pageSize=10`으로 파일 목록을 확인했다. 예: [Images and Text 메타데이터](https://www.kaggle.com/api/v1/datasets/view/nirmalsankalana/fashion-product-text-images-dataset), [Fashion Style 파일 목록](https://www.kaggle.com/api/v1/datasets/list/zara2099/fashion-style-image-dataset?pageSize=10). 공개 API 응답은 변경될 수 있으므로 실제 도입 시 버전과 라이선스를 다시 기록해야 한다.

데이터셋 전체를 받지 않았으므로 실제 파일의 무결성·해상도 분포·중복 해시·클래스 불균형·이미지 링크 생존율·라벨 정답률은 미측정이다. 이를 검증하기 전에는 공개 설명의 이미지 수나 라이선스 표기를 학습 데이터 품질 보증으로 해석하지 않는다. 이 보고서는 데이터 선택 평가이며 모델을 학습했거나 성능이 향상되었다는 보고가 아니다.
